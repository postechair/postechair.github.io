포지션 개요

AIR센터는 학내 행정업무를 AI 기반으로 전환(AX)하는 조직으로, 현업에 들어가 변화를 만드는 AX 엔지니어 파트와 그 변화를 뒷받침하면서 동시에 통제하는 AI 플랫폼 파트의 2파트 체계로 운영됩니다.

플랫폼 리드 엔지니어는 AI 플랫폼 파트를 이끌며, 센터의 기술 기반 전체(LLM 게이트웨이, 내부 자체 모델 서빙, 공용 RAG 스택, Application Architecture 및 개발 표준, 배포 체계, 거버넌스 정책)를 설계하고, 구축하고, 운영합니다.

이 포지션의 본질은 가속과 통제를 동시에 하는 일입니다.
AX 엔지니어팀이 빠르게 만들고 빠르게 배포할 수 있도록 아키텍처·표준·자산을 공급(Support)하는 동시에, 무엇이 어디로 나가는지 항상 아는 상태를 유지(Control)해야 합니다.

경험해볼 수 있는 업무

Control 축
  • LLM 게이트웨이 구축·운영 — 외부 API(Claude, OpenAI 등)와 내부 자체 모델(온프레미스 서빙)을 아우르는 단일 창구. 모델 종류와 무관하게 인증·사용량·비용·감사 로그를 중앙에서 관측하고, 데이터 민감도에 따라 내부 모델과 외부 API로 자동 라우팅하는 정책 엔진 설계
  • 데이터 거버넌스 정책 수립 — 데이터 분류 기준을 정의하고, 이를 “어떤 데이터가 어떤 모델까지 갈 수 있는가”로 구체화. 개인정보·민감정보의 외부 LLM 전송 통제 및 반출 차단, 민감 데이터의 내부 모델 처리 원칙
  • AI 기반 개발·운영 프로세스 수립 및 관리 — 코딩 에이전트와 AI Agent가 개발·운영에 참여하는 것을 전제로 한 프로세스 정의. AI 생성 코드의 리뷰·검증·책임 소재 기준, 에이전트의 시스템 접근 권한과 실행 범위, 프롬프트·에이전트 정의의 버전 관리와 변경 통제, AI 참여 이력의 추적 체계. 사람이 만든 코드와 같은 기준으로 심사하되, 만들어지는 속도가 다르다는 전제에서 프로세스를 설계
  • 기술 표준 심사·관리 — 승인 모델(외부 API·내부 모델) 및 라이브러리 목록, 아키텍처 패턴 준수 여부, 모델·서비스 평가 기준
  • 자산 레지스트리 — 센터의 모든 자동화 서비스·자산의 목록·소유권·상태 관리
Support 축
  • Application Architecture 설계 및 제공 — 센터의 AI 서비스가 공유할 레퍼런스 아키텍처 정의. 서비스 구조 패턴, 계층 분리, 인증·권한 모델, 로깅·에러 처리, 외부 시스템 연동 방식. AX 엔지니어가 아키텍처의 고민 없이 시작할 수 있는 출발점을 제공
  • 개발 표준 수립 및 확산 — 코딩 컨벤션, 프로젝트 구조, 테스트·리뷰 기준, 문서화 규격을 정의하고 스캐폴드·템플릿·예제 코드로 체화. 표준을 문서로 배포하는 데 그치지 않고 AX 엔지니어 대상 가이드·교육·온보딩까지 수행 (주니어 비중이 높은 AX팀 구성상 특히 중요)
  • 내부 자체 LLM 서빙 인프라 — 온프레미스 오픈소스 모델 서빙 및 GPU 자원 관리·스케줄링, 모델 버전 관리, 성능·품질 평가 체계. 폐쇄망에서 민감 데이터를 처리할 수 있는 자체 모델 역량 확보가 플랫폼 자율성의 핵심
  • 공용 RAG 스택 — 임베딩, 벡터 DB, 문서 ingest 파이프라인, 검색 품질 (RAG 엔지니어와 협업)
  • 폐쇄망 개발·배포 체계 — 패키지 미러, 컨테이너 레지스트리, CI/CD 템플릿
  • 공용 자산화 — 공통 라이브러리, 템플릿, 내부 SDK (내부 모델·외부 API를 동일한 인터페이스로 호출하는 추상화 포함)
  • 학내 시스템 연동 표준 인터페이스 제공
플랫폼 전략 및 자산화 루프 운영
  • 구축 범위 및 우선순위 수립 — 플랫폼 자체 구축에 있어서 주요 기술 요소를 설계하고, 센터 전략 및 사업 목표에 맞추어 단계적 구축 및 통합 방향의 사업 계획 수립. 외부 API 의존에서 내부 자체 모델로 이전하는 단계와 시점의 판단 포함
  • Fast Deploy & Re-Build 접근 실행 — 최소 기술 가이드라인으로 AX 엔지니어의 Fast Deploy를 허용하고, 플랫폼 성숙 단계에 맞춰 Re-Build & Integration 수행
  • 자산화 루프 가동 — AX 엔지니어의 반복 패턴의 가치·유지비용 평가 → 공용 자산으로 모듈화 구현 → 공통 자산의 재사용 확인
